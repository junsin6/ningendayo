# 人間だよ (Ningen da yo) — 日本語 AI クセ除去ツール

AI（ChatGPT・Claude・Gemini など）が書いた日本語を、**内容を一字も変えずに**文体・リズム・表現だけ自然な日本語へ戻す Claude Code スキルです。

翻訳調、カタカナ語の氾濫、機械的な並列（「まず・次に・最後に」）、「結論として／示唆に富む」のような AI 特有の常套句、「〜となっている」状態叙述の濫用、です・ます体の単調反復、文頭接続詞の多用、絵文字・箇条書きの濫用など、**10 大カテゴリ × 40+ サブパターン**を深刻度（S1/S2/S3）で分類し、span 単位で検出して推敲します。

## なぜ日本語特化なのか

英語圏の humanizer（QuillBot・Undetectable AI など）は日本語に弱い。そして日本語の AI クセは、英語とも他言語とも違う固有の重心を持ちます。

* 「ビジネス**における**意思決定」→「ビジネスの意思決定」（A-1）
* 「改善する**ことができる**」→「改善できる」（A-5）
* 「課題**となっている**」→「課題だ」（A-6・日本語で特に強いクセ）
* 「この**フレームワーク**を**レバレッジ**して」→「この枠組みを活かして」（B-2・カタカナ語）
* 「対応**が求められる**」→「企業は対応しなければならない」（I-4）
* 「いかがでしたでしょうか」→（削除・ブログ AI の決定的シグネチャ）

他言語ツールの手法をそのまま当てても日本語の自然なクセ除去にはなりません。日本語の助詞・文体（敬体／常体）・カタカナ語・状態叙述という固有現象を SSOT に整理し、検出・推敲・内容監査・自然度検証を分離したエージェントで実行します。

## 4 大鉄則

1. **意味不変** — 事実・主張・数値・固有名詞・直接引用は 100% 原文保存。
2. **根拠ベース** — 検出した span だけ手術的に修正。検出のない区間は触らない。
3. **文体維持** — 敬体／常体を変えない。コラムを文学に、レポートをエッセイに移さない。
4. **過推敲禁止** — 変更率 30% 超で警告、50% 超で強制中断。

## アーキテクチャ

```
入力テキスト
    ↓
[ai-tell-detector]          ── 検出 (span・category・severity)
    ↓
[japanese-style-rewriter]   ── finding ベースの手術的推敲
    ↓
[並列検証チーム]
    ├─ [content-fidelity-auditor]  ── 13 項チェックリストで意味等価性を監査
    └─ [naturalness-reviewer]      ── 検出再実行で残存・過推敲を判定
    ↓
[オーケストレーター総合]
    ├─ accept              → final.md + summary.md
    ├─ rewrite_round_2     → 2 次推敲（最大 3 回）
    ├─ rollback_and_rewrite → 問題 edit をロールバック
    └─ hold_and_report     → 人間レビューを推奨
```

## AI クセ分類体系（要約）

| ID | 大分類 | 代表サブパターン |
| --- | --- | --- |
| A | 翻訳調 | 「〜における」「〜について」「〜することができる」「〜となっている」「〜によって」受動 |
| B | 英語引用・カタカナ語過多 | 括弧併記の習慣、レバレッジ・シームレス等の不要カタカナ |
| C | 構造的 AI パターン | 機械的「まず／次に／最後に」、過度な箇条書き・見出し・絵文字 |
| D | AI 特有の慣用句 | 「結論として」「示唆に富む」「いかがでしたでしょうか」「革新的な」 |
| E | リズム均一性 | 文長の標準偏差が低い、です・ます／だ・である単調反復 |
| F | 修飾・重複 | 「非常に」「まさに」、同義二重修飾、「〜的／〜性／〜化」濫用 |
| G | ヘッジング濫用 | 「〜と考えられる」「〜のように見える」多重婉曲 |
| H | 接続詞多用 | 文頭「また／したがって／つまり／さらに」連発 |
| I | 形式名詞過多 | 「こと」「という点」「〜する必要がある」「〜が求められる」「〜能力」 |
| J | 視覚装飾濫用 | 過度な**太字**、鉤括弧、ダッシュ（—）濫用 |

詳細は [`ai-tell-taxonomy.md`](.claude/skills/humanize-japanese/references/ai-tell-taxonomy.md) ・ [`rewriting-playbook.md`](.claude/skills/humanize-japanese/references/rewriting-playbook.md)。

## 使い方 — 5 分でできます

### 0. 前提

[Claude Code](https://claude.com/claude-code) がインストールされていること。Mac・Windows・Linux すべて対応。

```
claude --version
```

> Claude Code はターミナルで Claude（Anthropic の AI）と対話しながらファイルを一緒に編集する CLI です。このリポのスキル・エージェントは Claude Code でのみ動作します（Web 版 Claude.ai や通常の ChatGPT では動きません）。

### 1. リポを取得

```
git clone <このリポの URL>
cd ningendayo
```

### 2. このフォルダの中で Claude Code を起動

```
claude
```

> **重要:** 必ず `ningendayo` フォルダ**の中で**起動してください。別の場所で起動するとこのリポのスキルが読み込まれません。

### 3. AI が書いた日本語を貼り付けて頼む

普段の言葉づかいで構いません:

```
この AI 文を自然に推敲して：

[ChatGPT / Claude / Gemini の下書きをここに貼り付け]
```

以下のどの言い方でもスキルが自動発動します:

* 「AI っぽさを消して」
* 「GPT っぽい文体を直して」
* 「人間が書いたように推敲して」
* 「翻訳調を直して」
* 「humanize して」

### 4. 結果を確認

Claude Code がこの順で処理します:

1. **検出** — どこがどの AI クセか、10 大カテゴリ × 深刻度で整理
2. **推敲** — 内容・数値・固有名詞・引用は保存し、文体・リズムだけ修正
3. **検証** — 意味が毀損していないか監査 + 再び AI っぽくないか再計測
4. **出力** — 推敲文、主要変更 diff、品質等級（A/B/C/D）、残存パターン

詳細な成果物はリポ内の `_workspace/{実行日-番号}/` に保存されます。

### 5. 結果が気に入らなければ

そのまま言えば大丈夫。コマンドを覚える必要はありません:

* **「この段落だけ推敲し直して」** — 当該箇所のみ再試行
* **「翻訳調だけもっと直して」** — 特定カテゴリのみ再処理
* **「推敲を弱めて」** — 保守的推敲（決定的パターンのみ除去）
* **「原文のトーンをもっと残して」** — 変更率上限を下げる
* **「2 次推敲して」** — 現結果をもう一度仕上げる

## Do-NOT リスト（検出・推敲の対象外）

* 数値・単位・日付
* 固有名詞・人名・製品名・モデル名
* 鉤括弧「」内の直接引用
* 法令・規定の条文
* 学術概念語（不可避な場合）

## ライセンス & 倫理

* 本ツールは「AI 検出器の回避（Undetectable AI）」ではなく、**日本語の文章品質改善**を目的とします。
* 学術提出・ジャーナリズムの真正性を保証するツールではありません。
* 分類体系（`ai-tell-taxonomy.md`）は研究・教育目的で自由に利用できます。
