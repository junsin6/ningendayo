# 推敲プレイブック (Japanese Rewriting Playbook) v1.0

`ai-tell-taxonomy.md` で検出された各カテゴリを、**意味を一字も変えずに**文体・リズム・表現だけ自然な日本語へ戻すための置換レシピ集。推敲役（`japanese-style-rewriter`）の作業マニュアル。

## 大原則（推敲前に必ず読む）

1. **意味不変**: 事実・主張・数値・固有名詞・直接引用は 100% 原文保存。
2. **根拠ベース**: 検出 finding のある span のみ手術的に修正。検出のない区間は触らない。
3. **文体維持**: 原文が敬体（です・ます）なら敬体のまま、常体（だ・である）なら常体のまま。**文体そのものを変えない**。コラムを文学に、レポートをエッセイに移さない。
4. **過推敲禁止**: 変更率 30% 超で警告、50% 超で強制中断。

## 文体の判定と固定

推敲の最初に入力文体を判定し、全編で固定する:

* 文末が「です・ます・でしょう」中心 → **敬体**。修正後も敬体。
* 文末が「だ・である・た」中心 → **常体**。修正後も常体。
* 混在 → 多数派に寄せず、原文の混在比率を尊重（無理に統一しない）。AI クセは「単調反復」であって「混在」ではない。

## カテゴリ別レシピ

### A. 翻訳調

| パターン | Before | After |
| --- | --- | --- |
| A-1 における | 教育**における**課題 | 教育の課題 / 教育現場の課題 |
| A-2 について | 環境**について**考える | 環境を考える |
| A-3 を通じて | 対話**を通じて**理解する | 対話で理解する / 話して理解する |
| A-4 に基づいて | 事実**に基づいて** | 事実から / 事実をもとに（1回まで） |
| A-5 することができる | 改善する**ことができる** | 改善**できる** / 改善する |
| A-6 となっている | 問題**となっている** | 問題だ / 問題になっている（変化を言う時のみ） |
| A-7 を持っている | 強みを**持っている** | 強みがある |
| A-8 によって（受動） | 政府**によって**定められた | 政府が定めた |
| A-9 のために | 成長**のために** | 成長できるよう / 成長を目指して |
| A-10 抽象主語+万能動詞 | 本調査**は**傾向**を示している** | 本調査から傾向が見える / 調査では〜だった |
| A-11 名詞羅列 | 売上拡大施策実行 | 売上を伸ばす施策を実行する |
| A-12 二重否定 | 効果が**ないとは言えない** | 効果はある / 効果が見込める |
| A-13 という | 革新**という**概念 | 革新（「という」削除） |

**注意**: A-4 / A-9 は一度なら自然。文書内 3 回以上の反復時のみ除去対象。

### B. 英語引用・カタカナ語

* **B-1 括弧併記**: 初出 1 回のみ残す。2 回目以降の「（AI）」「（LLM）」は削除。
* **B-2 カタカナ語**: 日本語で書けるものは開く。変換表:
  * レバレッジ → 活用 / てこ入れ
  * フレームワーク → 枠組み（技術文脈の固有語は維持）
  * インサイト → 示唆 / 気づき
  * コミット → 注力 / 約束
  * ソリューション → 解決策
  * シームレス → 滑らか / 切れ目なく
  * ロバスト → 堅牢
  * 句レベル（副詞/形容詞＋動詞のカタカナ連結）は単語表で引けないので**句ごと**開く: ディープにインテグレート → 深く溶け込む、イノベーションをドライブする → 革新を後押しする。
  * 近接同義カタカナの二重（メリット／アドバンテージ 等）は一方を述語・形容詞へ吸収して重複解消。
  * **定着カタカナ免責リスト（B-2 から半免責・和語化しない）** — 開くとかえって不自然/冗長になる業界標準語:
    * 生成 AI/技術系: Transformer・API・SDK・トークン・GPU・LLM・AI・エッジAI・IoT・クラウド・データ・ネットワーク・デバイス・サーバー・アーキテクチャ・システム・ユースケース・アップロード・オペレーション
    * 一般定着語: ルーティン・モチベーション・データドリブン
    * 境界事例（文脈判断）: リアルタイム性・モビリティ — 定訳が業界標準として通用するなら保持、平易文脈なら「即時性」「移動」等へ。判断に迷えば保持し残差 S3 固定。
  * 例外維持: 上記免責リスト＋固有名詞・製品名・モデル名。
* **B-3 英語引用**: ニュアンスが本当に必要な場合以外は日本語に開き、出典のみ併記。

### C. 構造

* **C-1 まず・次に・最後に**: 3 つのうち 1〜2 つを叙述に溶かす。順序語を消しても流れで伝わるか確認。
* **C-2 箇条書き**: エッセイ・コラムでは散文化。レポートで列挙が本当に効く箇所のみ残す。
* **C-3 / C-6 見出し・要約ボックス**: 散文なら削除。レポートなら見出しを具体化。
* **C-4 topic sentence**: 一部段落を事例・場面・引用始まりに変える。
* **C-5 絵文字**: エッセイ／レポートでは全削除。
* **C-7 一方・しかし・結局公式**: 3 連続のうち 2 つを削除し、接続詞なし段落を混ぜる。
* **C-8 Aか、Bか対句**: 3 回以上なら 2 つを非対称に再配置。

### D. AI 慣用句

原則 **削除**。意味が必要なら具体語へ:

| Before | After |
| --- | --- |
| 結論として、〜だ | （削除して直接結論を述べる） |
| 〜と言えるだろう | 〜だ（断定） |
| 非常に重要だ | （削除 or 核心だ / 具体的根拠） |
| 革新的な手法 | （具体的に何が新しいか書く） |
| いかがでしたでしょうか | （削除） |
| 示唆に富む | （何を示すのか具体的に） |
| 〜の地平を開く | 〜を可能にする / 〜を変える |
| 〜すべき時だ（結び） | 〜する（具体動詞の断定、1回まで） |
| 擬人化主語（D-5） | 行為者へ主語交換、擬人化動詞を弱める |

### E. リズム

* **E-1 文長均一**: 段落ごとに短文（10〜20字）を 1〜2 個、長文（90字+）を 1 個混ぜる。
* **E-2 文末単調**: 同一文体内で文末を変奏。
  * 敬体: 「〜です」の連続に「〜でしょう」「体言止め」「〜ます」を散らす。
  * 常体: 「〜だ」「〜である」「〜た」「体言止め」「〜のだ」を混ぜる。
  * **文体（敬体/常体）自体は変えない**。
* **E-3 段落均一**: 1 文段落 / 6 文段落を意図的に混ぜる。

### F. 修飾・重複

* **F-1 程度副詞**: 「非常に・とても・極めて・まさに」大半削除。
* **F-2 二重修飾**: 「重要かつ中心的」→ どちらか一方。
* **F-3 機能+役割**: 「役割と機能」→ 一つ。
* **F-4 〜的/〜性/〜化**: 動詞句・具体名詞へ解体。密度を半減。
* **F-5 〜性連鎖**: 動詞・形容詞へ開く。文書内 2〜3 回以下。

### G. ヘッジング

* **G-1**: 断定できる箇所は断定へ。「〜と考えられる」を必要箇所のみに。
* **G-2 二重婉曲**: 「可能性があると考えられる」→ 一つだけ。

### H. 接続詞

* **H-1 文頭接続詞**: 70% 削除。論理は内容で示す。
* **H-2 逆接**: 半分以上削除。
* **H-3 これは〜**: 前文と接続、または具体叙述へ。
* **H-4 つまり/すなわち**: 「言い換えれば」「要は」へ変奏 or 削除。文書内 2 回以下。

### I. 形式名詞

* **I-1 こと/ということ**: 断定叙述へ直結。
* **I-2 という点/面/意味で**: 具体名詞・動詞へ。
* **I-3 する必要がある**: 「すべきだ」or 具体勧告。
* **I-4 が求められる/が必要だ**: 主語・動詞で具体化。
* **I-5 〜能力/〜力連鎖**: 動詞形へ。文書内 2 回以下。

### J. 視覚装飾

* **J-1 太字**: 本文中はほぼ削除。
* **J-2 鉤括弧**: 引用・特殊用例のみ。
* **J-3 ダッシュ**: 読点・括弧・別文へ分解。1〜2 回以下。
* **J-4 括弧補足**: 大半を本文化 or 削除。

## 推敲しない（Do-NOT）リスト

検出も推敲もしない:

* 数値・単位・日付・割合
* 固有名詞・人名・製品名・モデル名・地名
* 鉤括弧「」内の直接引用
* 法令・規定の条文
* 学術概念語（不可避な場合）
* コードブロック・URL・数式

## 変更率の数え方（分離計上 — IMP-001, 適用 2026-09-06）

単一の change_rate は「正当な削除・和語化」と「過推敲」を区別できず、B-2 カタカナ濫用や敬語冗長の圧縮で機械的に膨張する。以下のとおり **2 軸で分離計上**する。

* **計算法**: 変更区間ごとに `Levenshtein(before, after)`（置換は 1 文字＝1 とみなす近似）を用いる。単純な「挿入+削除の和」は同一置換を二重計上するため使わない。複数 finding が 1 スパンへ結合する場合は**結合 edit として 1 回だけ**数える（二重計上禁止）。
* **語句改変率** = 意味担持語の置換・言い換えで動いた文字数 / 原文文字数。← 過推敲の主指標。
* **構造/削除率** = 接続詞・順序語・装飾・常套句・結びの純削除、文分割・語順再構成で動いた文字数 / 原文文字数。
* **挿入率**を単独併記し、`del ≫ ins`（削除主導・純減型）は中断対象から除外する。

### 閾値（判定は SKILL.md §総合判定が最終決定）

* **語句改変率 30% 超** → `summary.md` に警告を記録し続行。
* **語句改変率 50% 超** → 中断相当（`hold_and_report` 候補）。原文を尊重しすぎ／ジャンル移動を再点検。
* **合計 change_rate が 30%/50% を超えても、超過の主因が (a) B-2 カタカナの正当な和語化、(b) 敬語・常套句・装飾の純削除（del≫ins）であり、fidelity=pass かつ自然度 A/B かつ過推敲シグナル 0 のときは `override accept`**（IMP-001 既知欠陥）。summary に override 理由と 2 軸内訳を明記する。
* 実績: 2026-09-06-001（合計 37%＝語句 32.3%＋構造 4.4%、B-2 和語化 15 件が主因）を override accept。2026-09-06-002（合計 24.6%、削除 107≫挿入 44 の純減型）は閾値内で accept。

## 文体変換例（before → after 一括サンプル）

**Before（典型的な AI 文・敬体）:**
> AI 技術における進化は非常に目覚ましく、ビジネスに対して大きな変革をもたらすことができると言えるでしょう。まず、業務効率化を通じて生産性を高めることが可能となっています。次に、データに基づいた意思決定が求められます。

**After（推敲後・敬体維持）:**
> AI の進化はめざましく、ビジネスを大きく変えます。たとえば業務を効率化すれば生産性が上がる。データを見て意思決定する企業も増えました。

* 「における」「に対して」「を通じて」「に基づいた」（A 系）を解体
* 「もたらすことができる」「可能となっています」（A-5/A-6）を断定へ
* 「非常に」（F-1）、「と言えるでしょう」（D-1）を削除
* 「まず・次に」（C-1）を 1 つに、文末を変奏（E-2）
* **敬体は維持**、意味（AI が生産性と意思決定を変える）は保存
