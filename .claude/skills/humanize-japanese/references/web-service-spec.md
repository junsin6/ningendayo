# Web サービス仕様 (Web Service Spec) — Phase 5 拡張用

`humanize-japanese` パイプラインを Web アプリとして提供する場合の設計仕様。`humanize-web-architect` エージェントが参照する。CLI 版が安定してから着手する拡張フェーズ。

## スタック

* **フロント/サーバー**: Next.js 15 App Router
* **実行環境**: Vercel Fluid Compute
* **モデル接続**: Vercel AI Gateway 経由で Claude を呼び出し
* **状態**: v0 はステートレス（匿名・単一呼び出し）

## UX — 4 画面フロー

1. **入力**: AI が書いた日本語テキストを貼り付け。文体（敬体／常体）は自動判定、手動上書き可。
2. **検出ハイライト**: 検出された AI クセを span 単位でハイライト表示。カテゴリ別に色分け、深刻度バッジ（S1/S2/S3）。
3. **左右 diff**: 原文（左）と推敲文（右）を並べ、変更箇所を強調。各変更にカテゴリと理由をツールチップ表示。
4. **推敲文コピー**: 最終推敲文をワンクリックでコピー。品質等級（A〜D）と残存件数を併記。

## API 境界

CLI 版のコアロジックを共有し、3 エンドポイントに分離:

* `POST /api/detect` — テキスト → 検出 JSON（`02_detection.json` 相当）
* `POST /api/rewrite` — テキスト + 検出 JSON → 推敲文 + diff
* `POST /api/verify` — 原文 + 推敲文 → fidelity 監査 + 自然度レビュー

オーケストレーションはサーバー側で 3 つを順次/並列に呼ぶ。

## ロードマップ

* **v0 MVP**: 匿名・単一呼び出し・履歴なし。検出ハイライト + diff + コピー。
* **v1**: ログイン・推敲履歴の保存。
* **v2**: Pro/Team プラン・公開 API・Webhook。
* **v3**: Chrome 拡張（任意のテキスト欄でその場推敲）。

## 設計原則

* コアロジック（検出→推敲→検証）は CLI とリポジトリ共有。Web 固有部分（UI・認証・課金）だけ別レイヤー。
* レイテンシ対策: 検出と推敲はストリーミング表示。長文は段落単位でチャンク処理。
* プライバシー: v0 は入力テキストを保存しない。v1 以降の保存はオプトイン。
