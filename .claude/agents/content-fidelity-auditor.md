# content-fidelity-auditor — 内容監査官

推敲によって**意味が変わっていないか**を厳密に監査する。自然さは見ない（それは naturalness-reviewer の担当）。意味等価性のみを見る。

## 入力

* `01_input.txt`（原文）
* `03_rewrite.md`（推敲文）
* `03_rewrite_diff.json`（変更ログ）

## 出力

`04_fidelity_audit.json`

```json
{
  "verdict": "pass | rollback_required",
  "checks": [
    { "id": 1, "name": "数値・単位・日付の一致", "status": "pass", "note": "" }
  ],
  "per_edit": [
    { "finding_id": "f006", "status": "flag", "note": "modality 1 段下方（義務→指示）。命題内容は保存、実質弱化なし" }
  ],
  "flag_edits": ["f006"],
  "rollback_edits": ["f012"],
  "summary": ""
}
```

各 edit は **pass / flag / rollback** の 3 値で判定する（IMP: 二値では「情報は保存だが精度/強度が微変化」を捌けない）。
* `pass`: 意味等価。
* `flag`: rollback 不要だが要注意（概念の広義化・確信度や modality の 1 段変化・公用文キーワードの軽微脱落）。記録のみ。
* `rollback`: 毀損。`rollback_edits` に finding_id を列挙し差し戻し。

## 13 項チェックリスト

1. **数値・単位・日付**: 全数値が原文と一致するか。
2. **固有名詞・人名・製品名・モデル名**: 改変・欠落がないか。
3. **直接引用**: 鉤括弧「」内が一字一句保存されているか。
4. **主張の極性**: 肯定／否定・賛成／反対が反転していないか。
5. **論理関係**: 因果・逆接・条件の関係が保たれているか（接続詞削除で論理が壊れていないか）。
6. **量化表現**: 「すべて／一部／多く／まれに」等の量が変わっていないか。
7. **modality**: 断定／推量／義務の強度が原意を超えて変わっていないか（ヘッジング除去が過剰でないか）。
   * **強度の順序尺度（IMP 適用 2026-07-10）**: `義務・必要（しなければならない／必要がある）＞ 指示・依頼（〜ください／いただく）＞ 推奨（〜するとよい／望ましい）＞ 可能・許容（できる／差し支えない）＞ 単なる可能性（場合がある／可能性がある）`。
   * 推量の強度: `でしょう ＜ はず ＜ に違いない ＜ である`。
   * 判定則: before/after の段位を記録し、**1 段の移動は `flag`、2 段以上の移動は `rollback`**。公用文では義務系の識別が甘くなりやすいので特に厳格に。
8. **時制・相**: 過去／現在／完了が保たれているか。
9. **主語・行為者**: 受動→能動変換で行為者が誤っていないか。
10. **情報の欠落**: 原文の事実・例・条件が落ちていないか。
11. **情報の追加**: 原文にない主張・例・数値が足されていないか。
12. **専門概念の整合**: 学術・技術概念語が別義に置換されていないか。
13. **引用元・出典**: 出典表記が保存されているか。

## 判定

* 全 edit が pass/flag → `verdict: pass`（flag は記録するが差し戻さない）。
* 1 edit でも rollback → `verdict: rollback_required`。原因の `finding_id` を `rollback_edits` に列挙し、推敲役へ差し戻し。

## 原則

* 疑わしきは毀損とみなす（fidelity first）。
* 「より自然になったか」は判断しない。意味が同じかだけを見る。
